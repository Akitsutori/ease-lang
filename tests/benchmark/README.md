# Ease `llms.txt` Benchmark

This folder measures whether `llms.txt` alone is sufficient for a small LLM (`flash_lite`) to:
1. Write compiler-verified (`Check@1`), functionally correct (`Pass@1`), idiomatic (`IdiomScore`) Ease code.
2. Reason accurately about Ease semantics without executing code (`05_reasoning_trace`).

## Layout (Blind Separation)

- `prompts/<arena>.md` — Task prompts given to the test LLM alongside `llms.txt`.
- `hidden/<arena>/` — Hidden verification (`hidden_test.ease` + `rubric.json`, or `expected.json`), separated from `prompts/`.
- `submissions/` — Model outputs (`<arena>.ease` / `05_reasoning_trace.json`), gitignored.
- `results/latest.md` — Latest scorecard generated by `grade.go`, gitignored.
- `grade.go` — Deterministic Go grader (`llms.txt` coverage, `VERIFIED EXAMPLE`, `Check@1`, `Pass@1`, `IdiomScore`, trace).

## Manual Rerun Steps

1. Build the compiler:
   ```powershell
   go build -trimpath -ldflags="-s -w" -o ease.exe ./cmd/ease
   ```
2. For each prompt in `tests/benchmark/prompts/*.md`:
   - Give the target LLM **only** `llms.txt` + the prompt file (no tools, no repo access).
   - Save the raw Ease output (without markdown fences) to:
     - `tests/benchmark/submissions/01_unions_and_contracts.ease`
     - `tests/benchmark/submissions/02_relational_pipelines.ease`
     - `tests/benchmark/submissions/03_text_match_and_json.ease`
     - `tests/benchmark/submissions/04_concurrency_and_ecs.ease`
     - `tests/benchmark/submissions/05_reasoning_trace.json`
3. Run the deterministic grader:
   ```powershell
   go run ./tests/benchmark/grade.go
   ```
   The scorecard is printed to stdout and written to `tests/benchmark/results/latest.md`.
